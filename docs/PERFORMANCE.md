# 性能测量与范围

2026-10-20 在同一机器、固定工具链、JS release 目标上测量三个项目，本轮 JSJ222 更新至 ee7d3be（源码 0.2.0）。全部八组结果公开；本次优化后，本项目在八组的观测中位耗时均最低。这不是所有场景、平台或内存性能全面领先的证据。

## 当前三库基准

三次预热、七轮轮换项目执行顺序。单位为每个样本的毫秒；每行三者使用相同迭代数。环境、源码摘要、全部原始样本与样本最大值见 `reports/peer-benchmark.json`。七个样本的最大值不冒充 p95。

| 标量路径 | 每次解析 | 10000 | 3.641 | 5.336 | 7.252 |
| 标量路径 | 复用模板 | 10000 | 1.460 | 4.067 | 5.219 |
| Unicode 查询和列表 | 每次解析 | 10000 | 9.377 | 16.195 | 18.283 |
| Unicode 查询和列表 | 复用模板 | 10000 | 5.334 | 13.393 | 14.869 |

此前优化去除了每个百分号编码字节的重复字符表构造、保留字符检查的临时字符串，以及解析字面量时重复转换字符数组的路径；资源检查与展开语义保留。项目检查另改为编译后复用，但该 Node 工作流收益不包含在此核心基准中。

优化前的完整结果保留在 `reports/history/before-usability-20261020/peer-benchmark.json`，当时为六组最低。优化后首次测量保留在 `reports/history/usability-first-benchmark-20261020.json`，最终源码对应当前报告；未改变场景或迭代数。前后轮次并非同一次实验，不能把差值全部归因于代码，也不是每一行都比历史耗时更低。

## 方法与限制

运行 `npm run compare:peers` 后执行 `npm run benchmark:peers`。同一个生成的 benchmark 包引用三家核心，检查源码固定快照及当前核心副本；不包含 CLI、JSON 或网络成本。各样本包含一次绑定准备和初始解析；每次解析模式在循环里再次解析，复用模式复用初始对象。每个样本都检查输出长度校验和，超预算案例确认失败次数。

三者使用有界公开接口，但输入预算语义并不完全相同：本项目和 JSJ222 会检查绑定输入，Magic486 没有同等独立输入限额。大值失败场景使用 10,000 个 emoji 和 32 字节输出预算，其优势只针对该具体输入，不能外推成所有数据下的相同比例。

新增运行时类型契约与增量会话不在这八组核心展开负载中，不能由这些数字比较它们的成本。上一轮旧同类快照的完整结果保留在 `reports/history/before-runtime-contract-20261020/peer-benchmark.json`，不同轮次不用于隔离某个改动的收益。

下节另记录同一台 macOS 主机的四后端进程峰值 RSS；没有执行分配次数或跨操作系统/硬件测量，也没有统计显著性检验。小幅耗时差异可能落在运行抖动内。不根据本次结果写“所有场景最快”或“内存占用最低”。

## 复杂负载、四后端与进程峰值内存

新增 `npm run benchmark:resources`。固定上述同类提交，分别构建只引用一个库的 release 可执行文件；JS 直接启动 Node，wasm/wasm-gc 直接启动固定 moonrun，Native 直接启动可执行文件，计量中不运行编译器。每个对比项有 5 个新进程样本，轮换项目先后顺序；每个进程先做 3 次各 50 轮的预热。内部单调时钟只计业务循环；另记含启动、准备及预热的进程墙钟时间。原始数据、可执行文件摘要、源码摘要和运行命令见 `reports/peer-resources.json`。

四个固定场景：512 个独立表达式和 512 个标量绑定展开 500 次；512 条标量且必填规则验证 1000 次；200 个端点中一个变量交替更新 1000 次；200 个变量全部交替更新 200 次。契约与会话先编译再复用，准备不计入内部耗时。计量外检查实际字符串/旧快照与错误输入，循环内校验输出长度及重算数量；同类使用自身公开的有界接口。Magic486 无对应公开契约/会话入口，记为“不适用”，不制造替代实现进行排名。

本轮 16 组内部耗时的观测中位数均最低；Native 全更新和 wasm 全更新的优势较小，不作统计显著性结论。单位为一个样本完整循环的毫秒，不是单次请求延迟。

优化前完整样本保存在 `reports/history/before-resource-optimization-20261020/peer-resources.json`，当时核心为 7ffcefa；该历史报告含原始源码摘要和可执行文件摘要。两个中间阶段亦保存在同目录，未删去不利数据。保持场景、迭代数和预热流程后，本项目契约校验的观测中位耗时由 JS 119.477→28.310 ms、wasm 342.355→40.240 ms、wasm-gc 76.507→15.905 ms、Native 138.275→13.683 ms；前后是不同轮次，不能把全部差值归因于代码。

本轮实现去掉预算校验的临时文本数组和逐字符迭代对象；保留成员/单值/总量的错误优先级及 Unicode 码点语义。编译契约保存必填位置，成功校验无需再次生成完整诊断报告。无必填且允许额外绑定的计量路径仍检查前缀错误，但不分配缺失/未使用报告；会话复制已有绑定索引并仅遍历排序后的受影响端点。新增回归验证码点边界、错误优先级、首次引用定位与调用方修改输入后的行为。

仍待覆盖：目录策略审计、共享变量连接大量端点、混合长 Unicode/大集合、长期保留快照的内存增长、与合理的完整批量重算基线比较，以及 Linux/其他硬件。当前 16 组不能替代这些工作负载或第三方真实负载。

## 历史自比较

`reports/benchmark.json` 是 0.1.x 的历史“解析复用与重复解析”测量，不代表本轮候选版性能。`node tools/benchmark.mjs` 可重跑该自比较，但不得与本次三库结果混合排名。
