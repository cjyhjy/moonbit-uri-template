## 可复现的共同点和差异

共享探针在 JS/wasm-gc/Native 上输出一致。源文件位于 testdata/peer-smoke，预期值单独固定，执行失败不会被当作通过。

| 输入或任务 | 本项目 | Magic486 | JSJ222 |
| --- | --- | --- | --- |
| `/users/{id}{?tags*}`，id=team/a，tags=[a b,sdk] | `/users/team%2Fa?tags=a%20b&tags=sdk` | 相同 | 相同 |
| 非法 `😀{x` 的起点 | 1 码点 | 2 UTF-16 | 2 UTF-16 |
| `{?x}`，空列表预检 | omitted=1 | 无对应预检探针 | issues=0 |
| 同上必填检查 | OmittedBinding | 无对应必填探针 | 接受，展开为空 |
| `/users/{id}{?page}`，仅提供 id=42；要求 id 必填 | `/users/42` | 无对应必填探针 | expand_required 报 missing_variable，因为它要求 page 也存在 |
| `{x}`，x=emoji，输出预算 11 字节 | 拒绝 | 拒绝 | 拒绝 |
| `{?x,y}`，x=a,y=b；计量 | 8 字节 | 无对应计量探针 | 8 字节 |
| 同上来源映射 | 两条变量来源 | 无对应映射探针 | 一条表达式来源 |
| 同上两次批量展开 | 返回两项 | 无对应批量探针 | 返回两项 |

必填空集合是业务契约差异，不是对方 RFC 错误。JSJ222 可以使用其预检结果自行组合选择性必填；这里比较的是对应直接公开入口。

## 各自优势与当前局限

本项目的优势是 SDK 与可直接执行的项目工作流连接起来：定义契约、检查配置、定位文件、检查预算、解释输出，再用于实际客户端。新增的计量/批量等能力减少高级 SDK 差距；写入前预算避免 Magic486 当前片段已构造后才判断总量的分配路径，但没有据此宣称实测 RSS 更低。

Magic486 的 API 集中、默认有界、MoonBit 原生命令行和 MIT 许可仍有适用人群。性能结果仅针对固定工作负载，不能据此否定它在其他场景中的表现。

JSJ222 仍有更细的变量画像和跨目录批量审计接口。它已有编码前计量，不能将分配前预算描述成本项目独有。本项目现在提供跨模板整批计量/展开；项目检查与 Node SDK 复用已编译模板，已解决原先逐请求重复解析的问题。

本项目尚无长期第三方采用或跨平台统一性能/RSS 证据。旧核心便利 API 为兼容性保留无输入预算策略；需要调用有界入口。新增后端测试通过也不等于同类该后端不能工作。
