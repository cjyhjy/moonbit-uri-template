主题：moonbit-uri-template 补充材料与复审请求

MoonBit 开源大赛十月黑客松组委会老师您好：

感谢初审反馈。原申报以 RFC 6570 解析与展开为主，与 Mooncakes 上已有的同类库重叠。现补充说明本次新增的工作，请老师评估是否可以重新审核。

一、正确性。除 270 条上游标准用例外，新增与 Python uritemplate、std-uritemplate 两个参考实现的 644 条逐字节差分测试：583 条三方完全一致，其余每条分歧都给出了 RFC 依据。差分测试发现了一个三个 MoonBit 同类库都存在的问题：变量值含百分号序列时，前缀截断的结果与参考实现不同（例如 {x:3} 遇到 "%41bc"）。本项目已修正，并用共享探针在三个库上复现。

二、发请求前发现配置错误。可按业务声明必填变量和值类型，检查无用绑定和输入/输出预算。整份请求配置一次检查完，任一请求有问题就不生成任何 URL。错误可定位到 JSON 文件的行列，给出唯一候选的改名建议，并可输出 GitHub Actions 注解。

三、JS/TypeScript 直接接入。提供 Node SDK：从字面量模板推导变量名和必填项，数字、undefined 和对象顺序按 JS 习惯处理；支持模板目录、原子批量、升级差异比较，以及只重算受影响链接的增量会话。

四、真实下游。新增 GitHub 仓库巡检客户端，从独立解压的分发包运行，经预检后发出 9 个真实只读请求；参数切换场景下只重新请求 URI 发生变化的 2 条链接。

验证：四个后端（JS、wasm、wasm-gc、Native）各 336 项测试通过。与两个同类库同机对比，四后端共 36 组复杂负载的耗时中位数全部最低。
