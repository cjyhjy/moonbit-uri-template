主题：moonbit-uri-template 补充材料与复审请求——请求契约检查及真实 GitHub 接入

MoonBit 开源大赛十月黑客松组委会老师您好：

感谢初审反馈。我理解原申报以 RFC 6570 模板解析与展开为主要定位，与 Mooncakes 现有同类库存在直接重叠。本次希望补充说明新增的实际工作，并请老师评估这些增量是否能够支持重新审核。

本轮将项目扩展为“URI 模板库与请求契约检查工具”。除补齐计量、批量展开、模板目录、固定部分变量、策略和来源映射等主要能力外，新增重点是：

一、按业务选择必填变量，让路径参数必须存在、可选查询参数可以省略；区分缺失变量、会被省略的空集合和无用绑定，在发出请求前发现配置错误。
二、对整个请求配置执行检查和总资源预算控制，失败时不返回部分 URI；诊断可定位到 JSON 文件行列，处理转义字符和 emoji，并支持持续集成中的错误注解，以及唯一候选变量的拼写修复建议。
三、增加可直接安装的 JS/TypeScript SDK，提供模板名、变量名和必填参数提示，编译模板可重复使用；支持多模板目录的整批计量/生成、契约预检、策略审计和升级比较。已从本地 npm 压缩包在全新项目完成离线安装和运行、类型检查，尚未发布到 npm。
四、输出结果可追溯到每次变量出现的位置，配合同一核心的命令行与交互演示，方便复现和修复问题。新增完整变量画像、逐次修饰符变化、目录审计及升级比较；例如截断长度变化，以及模板文字不变但必填参数或运行时预算收紧，都可以给出直接报告。

为验证实际接入，我新增了 GitHub 仓库巡检客户端，并从独立解压的分发包运行。该客户端由本库生成请求 URL，实际读取本项目及两项同类项目的仓库信息、最新提交和发行列表，完成 9 个只读 HTTP 请求。附件保留请求状态、请求编号、响应摘要和版本信息。这是作者自建下游的真实联网案例，不是第三方生产采用证明。另有单独标记的故障注入记录，验证参数拼写错误、必填空集合和总预算超限时均不会发出网络请求。

验证方面，四个后端各通过 315 项测试，含逐条执行的 270 条固定上游语料；便携分发包解压后通过 78 项 SDK、命令行、项目检查与客户端离线测试。对比材料固定了 Magic486 和 JSJ222 的源码提交，保留双方原有优势、共同能力、共享输入结果及全部基准样本，不以测试数量或单个场景宣称全面领先。

本次附件对应 0.2.0 候选交付，仓库提供候选源码；正式 0.1.1 的发布记录与本次候选材料分开标明，源码推送不等于注册表新版本发布。补充材料包括可运行分发包及源码归档、差异说明、真实接入记录和复现步骤。仓库为：https://github.com/cjyhjy/moonbit-uri-template 。

我会按通知通过原报名记录更新材料，正式一页申报书由本人按表单要求撰写。烦请老师依据新增任务和实际交付重新评估；如果当前定位仍与既有项目重叠，也希望了解还需要补充哪些具体证据或调整范围。

感谢您审阅。
