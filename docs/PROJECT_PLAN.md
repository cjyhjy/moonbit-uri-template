# 项目规划

版本：原始计划 + 当前实施状态 · 2026-10-14

## 1. 项目目标

开发一个其他 MoonBit 项目能够直接依赖的 URI Template 库，帮助开发者把模板和变量转换成 URI 字符串。典型使用者是 API 客户端作者和 SDK 工具作者。

项目成功的衡量方式是：公开 API 易用、标准行为可验证、错误可定位、安装和示例可复现。代码行数不作为内部目标。

比赛路径沿用此前确定的新生态项目方向，争取月度验收并参与季度评选。官网源码标注十月报名和验收截止日期为 2026-10-31；评审安排与资格以正式通知为准。[赛事来源](https://github.com/moonbitlang/Hackathon2026/blob/main/src/App.tsx)

## 2. 范围与优先级

| 优先级 | 交付物 | 完成定义 |
| --- | --- | --- |
| P0 | MoonBit 核心库 | 模板解析、重复展开、变量查询、结构化错误 |
| P0 | RFC 6570 Level 4 | 全部标准操作符、复合值、prefix/explode；达到测试门槛后声明支持 |
| P0 | 标准测试与 CI | 固定上游数据版本，报告逐文件统计；JS、wasm-gc 核心库测试通过 |
| P0 | CLI 演示 | JSON 输入、URI 输出、错误退出码、三组可复现示例 |
| P0 | 开源交付材料 | README、许可证、参考来源、版本记录、验收报告 |
| P1 | Native 后端 | 有运行环境且同一测试集通过后正式声明支持 |
| P1 | 性能与复用示例 | 对比一次解析重复展开与每次重新解析，公开环境和原始结果 |
| P2 | 浏览器 Playground | 模板、变量、结果和错误展示，调用同一份 MoonBit 核心 |

首版不包含反向路由匹配、HTTP 请求、URL 规范化、完整 OpenAPI 解析、数据库、账号系统或远程服务。

Level 1–3 是中间里程碑和必要时的缩减版本，不把不完整的 Level 4 宣传为标准全支持。优先删除 P2/P1；如果核心仍延期，则明确发布实际完成的级别并同步申报范围，能否验收取决于主办方。

## 5. 分工和风险

我负责设计、实现、测试、CI 与文档草稿，解释关键语义和错误定位方式。你负责参赛身份、账号、报名、最终材料核对，以及能独立演示和解释项目；日程预留实际学习时间。

| 风险 | 处理方式 |
| --- | --- |
| 已有成熟同类库 | 正式申报前补查 Mooncakes 注册表与 GitHub；按兼容性、诊断或维护价值调整定位 |
| MoonBit 工具链变化 | M0 固定可用版本；CI 不随意跟随 nightly；升级单独验证 |
| Level 4 边界超预期 | 10/24 检查退出条件，先移除可选功能；保留真实支持范围 |
| Unicode / 编码出错 | 独立编码层、专项用例、多后端比较 |
| 测试数据与 RFC 有分歧 | 保存失败夹具与条款判断，公开差异，禁止静默跳过 |
| 发布或报名账号尚未具备 | 开发不依赖账号；10/15 前落实仓库、包命名空间和报名状态 |
| 官方截止时区不明 | 10/29–10/30 提交；向官方确认具体截止时刻 |

## 6. 最终交付包

一个公开仓库、一份可用的 Mooncakes 包（账号和发布条件落实后）、一套固定版本测试及 CI、一份 README 和 API 文档、三组 CLI 示例、一份带版本信息的测试报告、一份实际贡献与 AI 辅助说明。演示视频按正式验收要求准备，内部建议控制在 3 分钟。

演示顺序：用真实 API 地址模板说明用途；展示列表查询参数；展示非法模板如何定位；最后展示标准测试与下游导入代码。季度展示重点放在可复用性和可验证的工程质量上。

## 7. 当前实施状态

T01–T09 的实现和验证已完成，T10 的归档与注册表消费验证、公开仓库、远程 CI 和公开发布已完成；T11 的 Native 和四场景基准也完成。生态补查证实有同类，定位已更正为独立标准实现。正式报名由用户负责，尚无提交记录。Playground 仍为 P2 可选扩展，不作为首版必交项。
